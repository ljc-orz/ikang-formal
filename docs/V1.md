# 眼底指标预测 V1

V1 为每个 `result_*` 指标训练一个独立的二分类模型。输入为单眼彩照、年龄和性别；训练时左右眼作为两条样本，验证及测试时分别计算左右眼概率，再按患者取算术平均。

## 环境

推荐使用 Python 3.10 或 3.11，并安装：

```bash
pip install -r requirements.txt
```

默认的 torchvision 数据后端不需要安装 NVIDIA DALI。如需使用 CUDA 12 的 DALI GPU JPEG 解码与增强，另行安装：

```bash
pip install -r requirements-dali-cu12.txt
```

目标核心版本为 `torch==2.6.0`、`torchvision==0.21.0` 和 `timm==1.0.26`。GPU 训练默认使用 FP16 autocast 和动态 loss scaling；只有在配置中显式设置 `training.amp: bf16` 时才使用 BF16。CPU 运行会自动关闭混合精度。

## 数据

输入必须是 `data_prepare/build_webdataset.py` 生成的 paired-fundus WebDataset，根目录包含 `dataset.json`。缺失标签 `-1` 在训练和验证时被跳过，不参与 loss 或指标。

训练集默认保持原始标签分布（`data.train_sampling: natural`）。需要让每个训练
batch 保持二分类 1:1 时，可设置：

```yaml
data:
  train_sampling: balanced
```

也可在命令行或调度器的任务行中加入 `--train-sampling balanced`。该模式同时
适用于 torchvision 和 DALI：多数类按类别权重无放回抽取，少数类有放回抽取，
两类各占原始 epoch 的一半；左右眼始终成对保留，每轮都会重新抽样。原始患者
数为偶数时，均衡前后的 epoch 样本总数完全相同；为奇数时至多增加一个患者。
每个完整 batch 和整个 epoch 的标签比例都是 1:1，最后一个 batch 可能较小但
仍保持 1:1。当
`loss.pos_weight: auto` 时，平衡采样会自动使用 1.0，避免重复补偿类别不平衡；
显式指定的权重不受影响。为限制内存和解码开销，同一患者在一个 epoch 内只
缓存一份增强后的张量供重复抽样；下一 epoch 会重新增强并重新抽样。

默认训练集为 `train`，早停验证集为 `internal_validation`。类别权重从训练 tar 的 `labels.npy` 快速统计：

```text
pos_weight = min(阴性人数 / 阳性人数, 10)
```

可在配置中把 `loss.pos_weight` 改为 `null` 来使用普通 BCE，或填入正数指定权重。

## 训练

单个指标：

```bash
scripts/train.sh \
  --data-dir /path/to/webdataset \
  --targets result_alt \
  --output-dir runs
```

一次选择多个指标时，各自训练并保存独立模型：

```bash
scripts/train.sh \
  --data-dir /path/to/webdataset \
  --targets result_alt result_hba1c result_tg \
  --output-dir runs
```

默认参数见 `src/config/v1.yaml`。自定义配置只需写要覆盖的字段：

```yaml
training:
  batch_size: 48
  gradient_accumulation_steps: 3
  max_epochs: 20
checkpoint:
  primary_metric: val_auroc
```

然后增加 `--config my_config.yaml`。常用参数也可直接传入 `--epochs`、`--batch-size`、`--num-workers`、`--model`、`--pretrained-weights`。默认全局有效 batch 为 `64 × 2 = 128`。

### 可选 DALI 数据后端

不指定选项时仍使用原有的 WebDataset + Pillow + torchvision 路径，现有 `scripts/train.sh` 命令无需修改。要让 NVIDIA DALI 完成 WebDataset 读取、GPU JPEG 解码、随机裁剪、旋转、翻转、颜色扰动、Gaussian blur、缩放、CHW 转换和归一化，只需增加：

```bash
scripts/train.sh \
  --data-dir /path/to/webdataset \
  --targets result_alt \
  --output-dir runs \
  --data-backend dali --device cuda:0
```

DALI 后端要求数据包含 `build_webdataset.py` 生成的 `.idx` 文件，并要求偶数 `--batch-size`。训练 batch size 仍表示单眼图像数；DALI 内部每次读取其一半数量的患者并展开左右眼，因此不改变原有 batch 语义。DALI 的线程数、预取深度和 mmap 可在配置中设置：

```yaml
data:
  backend: dali
  dali_num_threads: 4
  dali_prefetch_queue_depth: 2
  dali_dont_use_mmap: false
```

独立评估同样支持 `--data-backend dali`。新 checkpoint 会保存训练时选择的后端，评估时也可以显式传 `--data-backend torchvision` 覆盖。DALI 未安装时只有显式选择 `dali` 才会报出安装提示，默认 torchvision 路径不会导入 DALI。

模型骨干默认是 `convnext_tiny.fb_in22k_ft_in1k`，预训练参数固定从仓库内的 `pretrained-weights/convnext_tiny.fb_in22k_ft_in1k/pytorch_model.bin` 加载，不访问网络；相对路径始终以项目根目录为基准。更换模型时，应通过配置中的 `model.pretrained_weights` 或命令行 `--pretrained-weights` 同时指定匹配的本地权重。整个训练过程中，stem 和前两个 stage 均冻结，只训练最后两个 stage、backbone head、metadata encoder 和融合分类头；不会进入全量解冻阶段。优化器对 backbone 和新增 head 分别使用 `1e-4` 和 `3e-4` 学习率，并采用 warmup + cosine decay。

也可以选择 RETFound-DINOv2 ViT-L/14。该模式加载精简后的本地 RETFound
backbone，冻结原始 backbone，仅在最后两个 Transformer block 的
`attn.qkv`、`attn.proj`、`mlp.fc1`、`mlp.fc2` 上训练 LoRA；metadata encoder
和融合分类头仍正常训练：

```yaml
model:
  backbone: retfound_dinov2
  lora_last_n_blocks: 2
  lora_rank: 8
  lora_alpha: 16.0
  lora_dropout: 0.0
```

也可直接增加 `--backbone retfound_dinov2`。默认权重路径是
`pretrained-weights/RETFound_dinov2_shanghai/RETFound_dinov2_shanghai_backbone.pth`；
`--pretrained-weights` 会覆盖当前所选 backbone 的权重路径。backbone 的创建和
微调策略分别位于 `src/model/backbones/` 下，新增种类时实现 builder 并注册到
factory 即可，无需修改融合分类器。

也可以使用本地 ImageNet-1K 预训练的 ResNet-50。`block` 指 `layer1` 到
`layer4` 中的 Bottleneck 残差块，共16个；先冻结整个 backbone，再按网络顺序
解冻最后 `n` 个 block。`src/config/resnet50.yaml` 默认设置为3，即解冻完整的
`layer4`：

```yaml
model:
  backbone: resnet50
  name: resnet50.a1_in1k
  pretrained_weights: pretrained-weights/resnet50.a1_in1k/pytorch_model.bin
  trainable_last_n_blocks: 3
```

每个指标目录会生成：

```text
runs/result_alt/
├── best.pt
├── last.pt
├── history.csv
├── training.log
├── run_config.json
└── summary.json
```

训练和每轮验证均使用 Rich 动态进度条，持续显示完成比例、batch 数、平均 loss、样本数、学习率、已用时间和预计剩余时间。`history.csv` 逐 epoch 保存训练与验证的完整指标、学习率、耗时、最佳模型状态和早停计数；`training.log` 追加保存启动配置、每轮训练/验证状态、完整 epoch 结果及最终摘要。

`best.pt` 默认按患者级 `val_auprc` 保存，并把验证集 Youden index 对应的阈值写入 checkpoint。可在配置里改用 `val_auroc` 等指标。

## 内部/外部测试

需要对同一 checkpoint 使用多个随机种子做随机增强推理时，可运行：

```bash
python infer.py \
  --checkpoint runs/result_alt/best.pt \
  --data-dir /path/to/webdataset \
  --split external_validation \
  --output-dir runs/result_alt/infer \
  --seeds 2026 2027 2028 \
  --data-backend dali
```

默认 `--transform train`，每个 seed 独立执行一次与训练一致的随机增强，并分别
生成一个 `.pt`；使用 `--transform eval` 时是确定性 resize，因此不同 seed 的
logits 应相同。文件只保存左右眼原始 logits、parquet `source_row` 和少量运行
元数据，其中 `logits[:, 0]` 是左眼，`logits[:, 1]` 是右眼。可按以下方式找回
构建 WebDataset 时原始 parquet 中的患者信息：

```python
import pandas as pd
import torch

result = torch.load("result_alt.external_validation.seed-2026.pt", weights_only=True)
parquet = pd.read_parquet(result["source_parquet"])
patient_info = parquet.iloc[result["source_row"].numpy()]
logits = result["logits"]
```

如果 parquet 移动过位置，可以读取当前路径，但必须是构建该 WebDataset 时使用
的同一份、且行顺序没有改变的 parquet。

### 多 GPU 推理队列

需要让不同 GPU 同时加载不同 checkpoint 推理时，复制
`scripts/infer/infer_jobs.example.txt` 并把每个任务写成一行。除下述 `seq`
简写外，每行参数与 `infer.py` 相同，但不要指定 `--device`；空行、整行注释和
行尾 `#` 注释都会被忽略。例如：

```text
--checkpoint runs/result_alt/best.pt --data-dir /data/fundus --split external_validation --output-dir runs/result_alt/infer --seeds seq 2026 2028 --data-backend dali
--checkpoint runs/result_scr/best.pt --data-dir /data/fundus --split external_validation --output-dir runs/result_scr/infer --seeds 2026 2027 2028 --data-backend dali
```

启动调度器：

```bash
python scripts/infer/schedule_infer.py my_infer_jobs.txt \
  --max-processes-per-gpu 1
```

调度器使用 PyTorch 可见的全部 GPU，按任务文件顺序把 `--device cuda:N` 加到
各子进程。`--max-processes-per-gpu` 控制每张卡的最大并发数；默认日志写到
`scheduler_logs/infer/<启动时间>/`。一个任务行中的多个 seed 会由同一个进程
依次推理；若要并行加载不同 checkpoint，应将它们写在不同任务行中。单个任务
失败不会阻止其余任务运行，全部结束后调度器会汇总失败任务并返回非零状态。
任务行还支持 `--seeds seq FIRST LAST`，它会展开为包含首尾的连续整数序列；
例如 `--seeds seq 2026 2028` 等价于 `--seeds 2026 2027 2028`。

### 多指标 logits 合并与 PCA

如果推理根目录下按 `alt`、`bmi`、`fbg` 等指标分目录，每个目录中保存该指标
不同 seed 的推理结果，可以将同一患者、同一 seed 的所有指标 logits 合成向量，
再统一降维：

```bash
python scripts/infer/reduce_predictions.py \
  --input-dir /DaTa/ljc_data/infers/resnet50_dali_balanced_ev \
  --output-file /DaTa/ljc_data/infers/resnet50_dali_balanced_ev.pca-m3.pt \
  --indicators alt bmi fbg hb hba1c hct hdl_c rbc scr tg wbc \
  --seeds seq 2026 2075 \
  --eye mean \
  --method pca \
  --n-components 3 \
  --pca-fit joint
```

`--eye` 可选 `left`、`right` 或 `mean`；`mean` 是左右眼原始 logits 的算术平均，
整个过程不计算 sigmoid。默认按子目录名称排序形成特征顺序，也可显式指定：

```bash
--indicators alt bmi fbg hb hba1c hct hdl_c rbc scr tg wbc
```

程序使用 `source_row` 对齐所有指标和 seed 的患者，而不依赖各文件内部的行顺序；
患者集合、split、增强模式、checkpoint 和 parquet 元数据不一致时会直接报出具体
文件。默认要求所有指标包含完全相同的 seed 集合，也可用 `--seeds` 选择子集。

`--pca-fit joint` 把所有 seed 的患者向量合并后拟合一套共享 PCA，因此不同 seed
的降维坐标具有相同含义。`mean` 在各种子 logits 的均值上拟合一套共享 PCA；
`per-seed` 则为每个 seed 独立拟合，适合单独分析，但不同 seed 的 PCA 轴不能
直接逐维比较。

输出文件可用 `torch.load(..., weights_only=True)` 加载，主要字段为：

```python
result = torch.load("resnet50_dali_balanced_ev.pca-m3.pt", weights_only=True)

result["X_prime"]   # [seed 数, 患者数, M]
result["seeds"]     # [seed 数]
result["source_row"]  # [患者数]，用于找回 parquet 患者信息
result["indicators"]  # X 原始 N 维特征的顺序

seed_index = (result["seeds"] == 2026).nonzero(as_tuple=True)[0].item()
X_prime_2026 = result["X_prime"][seed_index]  # [患者数, M]
```

文件还保存 PCA components、特征均值、解释方差比例、眼别、split、checkpoint 和
原 parquet 路径。

```bash
python evaluate.py \
  --checkpoint runs/result_alt/best.pt \
  --data-dir /path/to/webdataset \
  --split external_validation
```

独立评估入口是 `evaluate.py`，参数见上面的命令。

输出 CSV 包含 `left_probability`、`right_probability`、两眼平均后的 `probability` 和最终 `prediction`；同名 `.metrics.json` 保存 AUROC、AUPRC、敏感度、特异度和评估耗时，同名 `.log` 追加保留每次评估的完整结果。默认使用 checkpoint 内由内部验证集确定的阈值，必要时可显式传 `--threshold`，但不要用外部测试集重新挑选阈值。

## Smoke test

无需下载预训练权重，可用仓库示例数据跑一个 batch：

```bash
scripts/train.sh \
  --data-dir example/webdataset \
  --targets result_alt \
  --output-dir /tmp/ikang-v1-smoke \
  --model convnext_atto \
  --no-pretrained --device cpu --epochs 1 \
  --batch-size 4 --num-workers 0 \
  --max-train-batches 1 --max-val-batches 2

python evaluate.py \
  --checkpoint /tmp/ikang-v1-smoke/result_alt/best.pt \
  --data-dir example/webdataset \
  --split external_validation --device cpu \
  --batch-size 4 --num-workers 0 --max-batches 1
```

`--max-*-batches` 仅用于连通性检查，不应用于正式训练或正式评估。

## 多 GPU 训练队列

把每个训练任务写成参数文件中的一行，参数与 `train.py` 完全相同，但不要写
`--device`。空行和 `#` 注释会被忽略；路径中有空格时使用 shell 引号。可复制
`scripts/train_queue.example.txt` 后修改：

```text
--data-dir /data/fundus --targets result_alt --output-dir runs/alt --data-backend dali
--data-dir /data/fundus --targets result_hba1c --output-dir runs/hba1c --data-backend dali
```

任务行可重复使用 `--set section.key=value` 覆盖该任务配置文件中已有的任意叶子
字段；值按 YAML 语法解析，未知字段会报错。例如：

```text
--data-dir /data/fundus --targets result_alt --output-dir runs/resnet --data-backend dali --config src/config/resnet50.yaml --set training.max_epochs=20 --set training.backbone_lr=5e-5 --set model.trainable_last_n_blocks=5
```

以下命令会使用 PyTorch 能看到的全部 GPU，每张卡同时最多运行两个训练进程：

```bash
python scripts/schedule_train.py jobs.txt --max-processes-per-gpu 2
```

调度器按文件顺序启动任务，将 `--device cuda:N` 自动加入各任务。子进程的标准
输出和错误默认分别保存在 `scheduler_logs/<启动时间>/`，某个任务失败不会阻塞
其余排队任务，全部结束后调度器会返回非零状态并列出失败任务。

代码级快速测试可运行：

```bash
python -m unittest discover -s tests -v
```
